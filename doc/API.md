# BotCasino In-Game API

This document explains how to call the in-game API from Unity.

## Base URL

- Local/dev: `http://localhost:8080`
- Production: `https://your-domain.tld`

The API host/port comes from `.env`:

- `API_HOST` (default `0.0.0.0`)
- `API_PORT` (default `8080`)
- `API_SHARED_SECRET` (required for auth)
- `DEV_DISABLE_SIGNATURE` (default `false`, dev only)
- `ACHIEVEMENTS_EVENTS_CHANNEL_ID` (optional, channel for `achievement_unlocked`)

## Dev Mode (optional)

For local testing only, you can disable signature/timestamp verification:

```env
DEV_DISABLE_SIGNATURE=true
```

When enabled:

- `X-Timestamp` and `X-Signature` are not required
- requests are accepted without HMAC auth

Do not use this mode in production.

## Discord Announcements

The API can announce received in-game events in Discord.

Configuration priority:

1. DB value for event type (if already set)
2. Fallback `.env`:
   - `ACHIEVEMENTS_EVENTS_CHANNEL_ID=<channel_id>`

Supported announcement types:

- `achievement_unlocked`
- `daily_reward_collected`

## Live Achievements Board (Discord)

Admin slash commands:

- `/start_achievements` -> starts live tracking in the current channel and posts a global message
- `/end_achievements` -> pauses live tracking updates
- `/reset_achievements` -> resets achievement progress and live-board message links

When an achievement is unlocked while live tracking is active:

- A single pinned message is updated with one row per achievement:
  - `Current completions: X/Y | Next reward: 🪙 N`
  - unlockers (game IDs)
- A congrats message is posted mentioning the Discord user when linked

Tier color indicator by completion count:

- `⬜` -> `<3`
- `🟦` -> `>=3`
- `🟪` -> `>=5`
- `🟧` -> `>=10`

## Endpoints

### `GET /v1/health`

Health check.

Response:

```json
{ "status": "ok" }
```

### Rewards endpoints (Unity claim flow)

The rewards routes are available in both forms:

- Unversioned: `/rewards/...`
- Versioned alias: `/v1/rewards/...`

For Unity, you can use the unversioned routes below.

#### 1) `GET /rewards/{gamer_id}`

Returns rewards for one player (`gamer_id` is normalized to uppercase).

Optional query:

- `?collected=false` -> only pending rewards
- `?collected=true` -> only collected rewards
- omitted -> all rewards

Example:

`GET /rewards/PDNB83N1?collected=false`

Response:

```json
{
  "gamer_id": "PDNB83N1",
  "count": 2,
  "rewards": [
    {
      "reward_id": "3feff0b6-39cc-4303-a40f-9f31a3073819",
      "gamer_id": "PDNB83N1",
      "reward": { "Chests": ["Epic"] },
      "collected": false,
      "created_at": "2026-03-02T20:45:10.221441+00:00",
      "collected_at": null
    }
  ]
}
```

#### 2) `POST /rewards`

Marks one reward as collected (idempotent).

Request:

```json
{
  "gamer_id": "PDNB83N1",
  "reward_id": "3feff0b6-39cc-4303-a40f-9f31a3073819"
}
```

Success response:

```json
{
  "collected": true,
  "already_collected": false,
  "reward_id": "3feff0b6-39cc-4303-a40f-9f31a3073819",
  "gamer_id": "PDNB83N1"
}
```

If already collected:

```json
{
  "collected": true,
  "already_collected": true,
  "reward_id": "3feff0b6-39cc-4303-a40f-9f31a3073819",
  "gamer_id": "PDNB83N1"
}
```

Errors:

- `404 reward_not_found`
- `403 reward_not_owned_by_gamer`

#### 3) `POST /rewards/grant` (server-side helper)

Creates a pending reward for a gamer.
Useful for Discord/backoffice/server scripts. Unity usually does not call this route.

Request:

```json
{
  "gamer_id": "PDNB83N1",
  "reward": { "Chests": ["Epic"] }
}
```

`reward_id` is optional (auto-generated UUID if missing):

```json
{
  "gamer_id": "PDNB83N1",
  "reward_id": "custom-id-if-you-want",
  "reward": { "Keys": ["GoldenKey"] }
}
```

Success response:

```json
{
  "created": true,
  "reward_id": "3feff0b6-39cc-4303-a40f-9f31a3073819",
  "gamer_id": "PDNB83N1"
}
```

Error:

- `409 reward_id_already_exists`

### `POST /v1/events`

Main event ingestion endpoint for Unity -> BotCasino.

Required headers:

- `Content-Type: application/json`
- `X-Timestamp: <unix_seconds_utc>`
- `X-Signature: <hex_hmac_sha256>`

Auth/signature format:

1. Build payload string: `"{timestamp}.{raw_json_body}"`
2. Compute HMAC SHA256 with `API_SHARED_SECRET`
3. Encode as lowercase hex
4. Send in `X-Signature`

Timestamp tolerance is +/- 300 seconds.

## Request Body (common format)

```json
{
  "event_id": "uuid-v4-unique-per-event",
  "event_type": "achievement_unlocked",
  "player_game_id": "PDNB83N1",
  "payload": {}
}
```

Fields:

- `event_id` (string, required): unique idempotency key
- `event_type` (string, required): event kind
- `player_game_id` (string, required): ID generated by `/join`
- `payload` (object, optional): event-specific data

## Supported Event Types

### 1) `achievement_unlocked`

Recommended payload:

```json
{
  "arena": "FrostArena",
  "difficulty": "Brutal",
  "mods": ["Random", "HardCore"]
}
```

Allowed values:

- `arena`: `FrostArena`, `EternalMenagerie`
- `difficulty`:
  - for modded achievements (`Random`, `HardCore`, `NoDeath`): `Brutal`, `Torment`, `Infernal`
  - for no-mod achievements: `Easy`, `Normal`, `Hard`, `Painfull`, `Brutal`, `Torment`, `Infernal`
- `mods`: any combination of `Random`, `HardCore`, `NoDeath`

Achievement names are inferred from arena + mods:

- FrostArena + no mod -> `FrostArena`
- FrostArena + Random -> `Dicey`
- FrostArena + NoDeath -> `FrozenHeart`
- FrostArena + HardCore -> `HardCold`
- FrostArena + Random+HardCore+NoDeath -> `LegendOfTheNorth`
- EternalMenagerie + no mod -> `Eternal Menagerie`
- EternalMenagerie + Random -> `Randomicon`
- EternalMenagerie + NoDeath -> `CorruptedHeart`
- EternalMenagerie + HardCore -> `HardlyHuman`
- EternalMenagerie + Random+HardCore+NoDeath -> `ConquereorOfTheEternal`

Only these 10 achievement combos are accepted.

Completion count increment rules:

- Modded achievements:
  - `Brutal` -> `+1`
  - `Torment` -> `+3`
  - `Infernal` -> `+5`
- No-mod achievements:
  - `Easy` -> `+1`
  - `Normal` -> `+2`
  - `Hard` -> `+3`
  - `Painfull` -> `+4`
  - `Brutal` -> `+5`
  - `Torment` -> `+6`
  - `Infernal` -> `+7`

Notes:

- Reward for unlocking player uses Tier 5 logic.
- Global thresholds are applied at 1 / 3 / 5 / 10 completions.
- Duplicate achievement per player is ignored (`already_claimed`).

Typical success response:

```json
{
  "accepted": true,
  "event_id": "2b0c8b13-80b8-42b1-a8dd-9f998516f8f7",
  "achievement_id": "LegendOfTheNorth",
  "arena": "FrostArena",
  "difficulty": "Torment",
  "mods": ["HardCore", "Random"],
  "count_increment": 3,
  "completion_count": 3,
  "coins_awarded": 60,
  "referral_bonus_awarded": 6,
  "global_threshold_reward": 40,
  "global_reward_recipients": 12
}
```

### 2) `daily_reward_collected`

Payload:

```json
{
  "collect_day_utc": "2026-02-24",
  "streak": 1
}
```

Fields:

- `collect_day_utc` (optional): defaults to today UTC when missing/invalid
- `streak` (recommended): used for both points and coins formulas

Daily reward formulas:

- points granted to race: `2^streak`
- player coins: `15 * streak`

Typical success response:

```json
{
  "accepted": true,
  "event_id": "a2d9ffab-a265-4497-97ab-67ddfcd18b7f",
  "collect_day_utc": "2026-02-24",
  "current_streak": 5,
  "points_awarded": 32,
  "total_points": 98,
  "daily_coins_awarded": 75,
  "referral_bonus_awarded": 1
}
```

If already collected on same day:

```json
{
  "accepted": true,
  "event_id": "a2d9ffab-a265-4497-97ab-67ddfcd18b7f",
  "already_collected_today": true,
  "collect_day_utc": "2026-02-24"
}
```

### 3) Unknown `event_type`

The API currently accepts and stores unknown event types without reward logic:

```json
{
  "accepted": true,
  "event_id": "....",
  "event_type": "some_future_event"
}
```

## Error Responses

### `401 Unauthorized`

- `stale_or_invalid_timestamp`
- `invalid_signature`

### `400 Bad Request`

- `invalid_json`
- `missing_required_fields`
- `invalid_arena`
- `invalid_difficulty`

## Idempotency Rules

- `event_id` is unique.
- Re-sending same `event_id` returns:

```json
{
  "accepted": true,
  "already_processed": true,
  "event_id": "same-id"
}
```

Always generate a new UUID per event.

## Unity C# Example (signature + POST)

```csharp
using System;
using System.Security.Cryptography;
using System.Text;
using System.Threading.Tasks;
using UnityEngine;
using UnityEngine.Networking;

public static class BotCasinoApiClient
{
    public static async Task SendEventAsync(string baseUrl, string secret, string jsonBody)
    {
        long ts = DateTimeOffset.UtcNow.ToUnixTimeSeconds();
        string timestamp = ts.ToString();
        string signedPayload = $"{timestamp}.{jsonBody}";
        string signature = ComputeHmacSha256Hex(secret, signedPayload);

        using var req = new UnityWebRequest($"{baseUrl}/v1/events", "POST");
        byte[] bodyRaw = Encoding.UTF8.GetBytes(jsonBody);
        req.uploadHandler = new UploadHandlerRaw(bodyRaw);
        req.downloadHandler = new DownloadHandlerBuffer();
        req.SetRequestHeader("Content-Type", "application/json");
        req.SetRequestHeader("X-Timestamp", timestamp);
        req.SetRequestHeader("X-Signature", signature);

        var op = req.SendWebRequest();
        while (!op.isDone) await Task.Yield();

        if (req.result != UnityWebRequest.Result.Success)
        {
            Debug.LogError($"BotCasino API error: {req.responseCode} {req.downloadHandler.text}");
            return;
        }

        Debug.Log($"BotCasino API ok: {req.downloadHandler.text}");
    }

    private static string ComputeHmacSha256Hex(string secret, string message)
    {
        using var hmac = new HMACSHA256(Encoding.UTF8.GetBytes(secret));
        byte[] hash = hmac.ComputeHash(Encoding.UTF8.GetBytes(message));
        var sb = new StringBuilder(hash.Length * 2);
        foreach (byte b in hash) sb.Append(b.ToString("x2"));
        return sb.ToString();
    }
}
```

## Integration Checklist

1. Run `/join` in Discord and store `player_game_id` in game profile.
2. Configure `API_SHARED_SECRET` on server and same secret in Unity secure config.
3. Send signed `POST /v1/events` for:
   - `achievement_unlocked`
   - `daily_reward_collected`
4. Use UUID `event_id` for every emitted event.
5. Retry network failures with backoff, but keep same `event_id` for retry of same event.
